# Sail LAN Boost Guideline Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship project-agnostic LAN shared-proxy guidance as an opt-in Laravel Boost guideline from `reyemtech/sail`, document discovery, verify safe composition in a consuming app, and remove the app-level duplicate.

**Architecture:** Extend Sail's existing `core.blade.php` with a focused LAN section and protect both legacy build guidance and new diagnostics with a rendered contract test. Current Boost stores third-party guidelines by package key, so multiple sorted files for one package overwrite each other and only the last survives. Document discovery in the LAN README section. Verify against the real consuming app with complete file snapshots and section-level before/after comparisons because Boost regeneration is also known to risk dropping unrelated guidance.

**Tech Stack:** Laravel Boost Blade/Markdown guidelines, PHPUnit, Composer package resources, Markdown, Git diff, Docker-backed Laravel Sail CLI.

## Global Constraints

- Base all package work on `origin/1.x`; the implementation branch is `feat/boost-lan-networking`.
- Preserve all existing build and Helm guidance in `resources/boost/guidelines/core.blade.php`; add the LAN section to that same file and do not create another package guideline file.
- Match the existing guideline style: Blade comment header, Markdown title, terse imperative bullets.
- Keep the guideline project-agnostic; do not include slot 3, `SAIL_SUBNET=172.21.0.0/24`, `VITE_PORT=5203`, or the app-specific Redis/Horizon note.
- Document current behavior only; do not change `HostRegistry`, `forwardPortMap()`, subnet allocation, or port allocation.
- Treat the consuming app as a dirty worktree. Never discard or overwrite pre-existing changes; restore from explicit snapshots if discovery is destructive.
- Do not create commits unless the user explicitly authorizes them.
- Do not claim successful end-to-end verification if any unrelated Boost section disappears.
- No new Composer dependencies.
- PHP tests run with `composer test`; static analysis runs with `vendor/bin/phpstan analyse src`.

## File Structure

- `resources/boost/guidelines/core.blade.php` (modify) - existing build/Helm guidance plus package-owned LAN collision and TLS/SNI diagnostics in the only Sail package guideline file.
- `tests/Unit/Boost/CoreGuidelineTest.php` (create) - rendered contract for preserved core guidance, required LAN guidance, exact Docker templates, forbidden project-specific values, and the single-file invariant.
- `README.md` (modify, near `Running on a LAN server`) - opt-in Boost discovery and destructive-update warning.
- `docs/superpowers/specs/2026-08-03-sail-lan-boost-guideline-design.md` (already created) - approved design record.
- `apps/laravel/.ai/guidelines/sail-lan-networking.md` (delete after safe discovery) - obsolete app-owned duplicate.
- `apps/laravel/CLAUDE.md` (regenerate and verify) - remove the hand-inserted `.ai` block and retain the package-composed `reyemtech/sail` section.
- Other Boost outputs in `apps/laravel` may be regenerated by Boost; snapshot and compare them, and retain changes only if no unrelated guidance is lost.
